# 서버 2 공유 챕터와 이야기

2026년 11월 21일 PM 요구사항의 공유 챕터 구조를 기준으로 한 첫 구현이다. 서버 1의 공통 API 브랜치를 기반으로 작성했으며 JdbcClient와 기존 세션·책 접근 검사·응답 래퍼를 재사용한다.

## 호출 순서

1. 서버 1 API로 두 사람이 책에 연결한다. 책 생성 시 기본 ‘초등학생 시절’ 챕터 하나가 생긴다.
2. GET /api/v1/books/{bookId}/chapters로 목록과 챕터 ID를 얻는다.
3. 각자 PUT /api/v1/chapters/{chapterId}/story로 자기 이야기 전체를 저장한다.
4. POST /api/v1/chapters/{chapterId}/story/complete로 각자의 작성을 완료한다.
5. 두 사람이 모두 완료하면 챕터 조회의 receivedMission에 상대 미션 문구가 표시된다. 상대 이야기 본문은 계속 null이다.

이야기 저장 입력 예시는 다음과 같다. PUT은 전체 저장이며 생략한 값은 빈 문자열이 된다.

```json
{
  "title": "첫 월급을 받던 겨울",
  "content": "퇴근 버스에서 노래를 들으며 집에 갔다.",
  "missionInstruction": "퇴근길에 좋아하는 노래 한 곡을 들어봐."
}
```

이름 최대 100자, 이야기 제목 200자, 본문 20000자, 미션 2000자를 제안값으로 적용했다. 임시저장은 빈 값으로 가능하고, 작성 완료는 제목·본문·미션이 모두 채워져야 한다.

목록과 상세는 myStory에 현재 참여자의 이야기만 반환한다. progress에는 두 사람의 작성 완료 여부만 포함한다. nextAction은 WRITE_STORY, WAIT, DO_MISSION 순서로 변한다. READ와 counterpartStory 공개는 후속 열림 처리에서 사용한다.

빈 챕터는 두 참여자 누구나 DELETE /api/v1/chapters/{chapterId}로 삭제할 수 있다. 제목·본문·미션 중 하나라도 있거나 작성 완료 이력이 있으면 409다. 저장·완료·삭제는 같은 챕터 행을 잠가 경쟁 요청을 순서대로 처리한다.

## 남은 범위

미션 후기 저장과 수정, 네 가지 완료 조건에 따른 챕터 열림, 읽음 상태, 푸시, 이야기 삭제는 후속 구현이다. 이 단계에서는 챕터가 자동으로 열리지 않는다. 본문과 음악을 미션과 함께 즉시 공개하던 이전 ERD·API 초안은 이 구현의 기준으로 사용할 수 없다.

Swagger UI에서 ‘챕터와 이야기’를 선택하면 6개 API를 확인할 수 있다. 배포 전후에는 DB 마이그레이션 V2 적용 여부와 프론트 origin의 PUT·DELETE CORS 허용을 확인한다.
