# 청춘교환 공통 시연 시나리오

프론트는 화면에서, 백엔드는 Swagger에서 같은 순서를 따른다. 기능 하나를 바꿀 때는 관련 행만 확인하고, 발표 전에는 전체 흐름을 확인한다. 세 참여자는 서로 구분되는 브라우저 환경이나 API 참여자 정보로 준비한다.

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1. 가족 연결 | 자녀가 엄마의 초대 링크로 연결하고, 아빠와도 별도로 연결한다. | 자녀의 책장에 ‘엄마 × 나’와 ‘아빠 × 나’ 두 권이 생긴다. |
| 1-1. 부모 간 연결·재수락 | 부모인 두 사람이 상대 호칭을 입력해 초대로 연결한다. 이미 수락한 기기와 제3의 기기에서 같은 링크를 다시 연다. | 역할 조합과 관계없이 책에는 두 자리만 생긴다. 수락한 기기는 기존 책으로 이동하고 제3의 기기는 참여할 수 없다. |
| 2. 공유 챕터와 초안 | 기본 ‘초등학생 시절’ 챕터를 열고 엄마가 이야기와 미션을 저장한다. | 두 사람의 목록에 같은 챕터가 보인다. 엄마 초안은 엄마만 읽고 자녀에게는 내용이 보이지 않는다. |
| 3. 각자 작성 완료 | 엄마가 작성을 완료하고 자녀도 같은 챕터에 자기 이야기와 미션을 저장·완료한다. | 한 명만 끝나면 WAIT, 둘 다 끝나면 DO_MISSION이다. 각자에게 상대 미션 문구만 보이고 상대 이야기 본문은 숨긴다. |
| 4. 후기와 열림 | 두 사람이 각자 상대 미션을 수행하고 감상을 제출한다. | 첫 제출 시 미션을 준 사람에게 완료 여부만 보인다. 두 감상이 모두 제출되면 챕터가 열리고 둘에게 이야기와 감상이 공개된다. |
| 5. 책별 접근 | 아빠가 엄마 책의 챕터를 직접 조회한다. | 챕터·이야기·미션 내용을 반환하지 않고 404다. |
| 5-1. 공통 참여 권한 | 책 참여자, 다른 책 참여자, 쿠키가 없거나 만료된 기기에서 같은 책을 조회한다. | 참여자만 `200`과 `success: true`를 받는다. 미참여와 없는 책은 같은 `404`, 세션 없음·만료는 `401`이며 실패 본문은 `success: false`와 `error.code`를 포함한다. |
| 6. 빈 챕터 삭제 | 자녀가 만든 빈 챕터를 엄마가 삭제하고, 작성 내용이 있는 챕터도 삭제해 본다. | 빈 챕터는 삭제되고 작성 내용이 있으면 409다. 삭제 푸시는 후속 구현이다. |
| 7. 미션 고정 | 두 사람이 이야기를 완료한 뒤 엄마가 공개된 미션 문구를 수정한다. | 미션 문구 변경은 409이며 자녀가 받은 미션과 제출한 감상은 그대로 유지된다. |

새 동작은 ‘상황 → 행동 → 기대 결과’ 순서로 한 줄을 추가한다. PR에는 확인한 단계를 표시한다. 예를 들어 모의 응답으로만 확인했다면 `단계 4 / 모의 응답 / 완료 표시와 감상 열기 확인 / 배포 API 연동 대기`로 적는다.

서버 2의 현재 구현 범위는 [공유 챕터와 이야기](서버2%20구현.md)를 따른다.

프론트와 API가 별도 오리진이면 배포된 프론트에서 `PUT`·`DELETE` 사전 요청과 참여자 쿠키를 확인한다. 같은 사이트의 HTTPS 배치를 기준으로 한다.

8. EC2 자동 배포 설정이 완료된 상황 → `main`에 변경을 병합한다 → Java 21과 MySQL 테스트를 통과한 JAR가 배포되고 Spring Boot와 Nginx 요청이 성공한다. 새 버전의 확인 요청이 실패하면 직전 JAR로 복원되고 해당 배포 작업은 실패로 표시된다.
