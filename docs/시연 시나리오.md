# 청춘교환 공통 시연 시나리오

프론트는 화면에서, 백엔드는 Swagger에서 같은 순서를 따른다. 기능 하나를 바꿀 때는 관련 행만 확인하고, 발표 전에는 전체 흐름을 확인한다. 세 참여자는 서로 구분되는 브라우저 환경이나 API 참여자 정보로 준비한다.

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1. 가족 연결 | 자녀가 엄마와 초대 코드로 연결하고, 아빠와도 별도로 연결한다. | 자녀의 책장에 ‘엄마 × 나’와 ‘아빠 × 나’ 두 권이 생긴다. |
| 1-1. 부모 간 연결·재수락 | 부모인 두 사람이 상대 호칭을 입력해 초대로 연결한다. 이미 수락한 기기와 제3의 기기에서 같은 링크를 다시 연다. | 역할 조합과 관계없이 책에는 두 자리만 생긴다. 수락한 기기는 기존 책으로 이동하고 제3의 기기는 참여할 수 없다. |
| 2. 챕터 공개 | 엄마가 ‘첫 월급을 받던 겨울’에 ‘퇴근길에 이 노래 듣기’ 미션을 담아 완성한다. | 자녀의 받은 미션과 엄마의 보낸 미션에 같은 미션이 한 건 보인다. 엄마에게 보이는 상태는 ‘수행 대기’다. |
| 3. 수행 전 | 자녀가 미션을 열고 ‘나중에 하기’를 선택한다. 빈 감상 제출도 확인한다. | 미션은 대기 상태다. 빈 감상으로 제출을 완료할 수 없다. |
| 4. 감상 제출 | 자녀가 ‘퇴근길에 들으니 엄마 이야기가 떠올랐어’라고 제출한다. 엄마가 To-do를 다시 연다. | ‘수행 완료’가 표시된다. 항목을 열면 엄마의 당시 기억과 자녀가 방금 쓴 감상이 함께 보인다. 자녀가 만든 챕터가 없어도 된다. |
| 5. 책별 공개 | 아빠의 To-do와 책장을 열고, 엄마 책의 챕터를 직접 조회해 본다. | 목록에 엄마의 미션이 보이지 않고, 직접 조회해도 챕터와 감상 내용이 공개되지 않는다. |
| 5-1. 공통 참여 권한 | 책 참여자, 다른 책 참여자, 쿠키가 없거나 만료된 기기에서 같은 책을 조회한다. | 참여자만 `200`과 `success: true`를 받는다. 미참여와 없는 책은 같은 `404`, 세션 없음·만료는 `401`이며 실패 본문은 `success: false`와 `error.code`를 포함한다. |
| 6. 반대 방향 | 자녀가 엄마 책에 별도의 챕터와 미션을 하나 작성한다. | 이번에는 엄마가 수행자다. 새 미션은 대기 상태이고 기존 미션은 완료 상태를 유지한다. |

새 동작은 ‘상황 → 행동 → 기대 결과’ 순서로 한 줄을 추가한다. PR에는 확인한 단계를 표시한다. 예를 들어 모의 응답으로만 확인했다면 `단계 4 / 모의 응답 / 완료 표시와 감상 열기 확인 / 배포 API 연동 대기`로 적는다.
