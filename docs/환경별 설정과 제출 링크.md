# 환경별 설정과 제출 링크

## 실행 환경

공통 DB 접속 정보는 `application.yml`에서 환경 변수로 받는다. 비밀번호와 배포 URL은 저장소에 넣지 않는다.

| 환경 | 활성화 | 초대 링크 주소 | 세션 쿠키 |
| --- | --- | --- | --- |
| 로컬 | `SPRING_PROFILES_ACTIVE=local` | 기본 `http://localhost:8080` | `Secure=false` |
| 배포 | `SPRING_PROFILES_ACTIVE=prod` | `INVITE_BASE_URL` 필수 | `Secure=true` |

배포에서는 HTTPS가 적용된 뒤 `prod` 프로필을 활성화한다. `INVITE_BASE_URL`은 API 서버가 아니라 프론트의 `/invite/{code}` 화면 주소를 지정한다. 프론트가 다른 오리진이면 `FRONTEND_ORIGIN`에 경로 없는 정확한 오리진을 지정한다. 같은 오리진으로 프록시하면 비워 둘 수 있다.

```bash
# 로컬 예시: DB_URL, DB_USERNAME, DB_PASSWORD를 먼저 설정한다.
SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
```

```bash
# 배포 환경 파일 예시: 실제 값은 EC2의 비공개 환경 파일에 둔다.
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://<db-host>:3306/hackathon
DB_USERNAME=<db-user>
DB_PASSWORD=<db-password>
INVITE_BASE_URL=https://<frontend-host>
FRONTEND_ORIGIN=https://<frontend-host>
```

기존 배포에서 프로필을 지정하지 않으면 기존 `application.yml` 기본 동작이 유지된다. HTTPS 및 프론트 오리진을 확인한 뒤 배포 프로필을 전환한다. 프론트와 API가 서로 다른 사이트라면 현재 `SameSite=Lax` 쿠키는 브라우저의 교차 사이트 요청에 실리지 않는다. 이 경우 같은 사이트의 HTTPS 주소 또는 동일 오리진 프록시로 배치하고 실제 브라우저에서 확인한다.

## 코드 품질 제출에 필요한 주소

| 제출 항목 | 준비 방법 |
| --- | --- |
| 코드 저장소 | `https://github.com/11thNeoHackathon/backend` |
| API 명세 | 배포 서버의 `/swagger-ui/index.html` 확인. 가족 연결과 챕터와 이야기 두 문서를 선택할 수 있어야 한다. |
| 배포 URL | HTTPS로 접속 가능한 실제 API 주소. IP 기반 HTTP 임시 주소와 구분한다. |

배포 이후에는 다른 기기 또는 시크릿 창에서 Swagger가 열리는지 확인한다. `POST /api/v1/participants`로 쿠키를 발급받고, 이어서 `GET /api/v1/participants/me`가 200인지 확인한다. 프론트에서는 `credentials: 'include'`로 같은 흐름을 시험한다.
